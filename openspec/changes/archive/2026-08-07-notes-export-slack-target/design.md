## Context

`ft notes export` renders a vault note (or original-file line range) as
clean, portable markdown via the `ExportTarget` seam in
`ft-core/src/export.rs`: the driver (`export_content`) handles
frontmatter clamping and range slicing — target-independent — and a
`transform_line(&self, line, LineContext) -> Option<String>` impl
renders each line. `CommonMarkExport` is the v1 impl. The capability
spec names `plaintext` and `slack` as planned targets.

Slack's mrkdwn is a small dialect: `*bold*`, `_italic_`, `~strike~`,
`` `code` ``, ```` ``` ```` blocks, `>` blockquotes, `- ` / `1. `
lists, `<url|text>` links, bare-URL autolinks. Everything else —
headings, `**bold**`, `[text](url)`, images, tables, `- [ ]` checkboxes,
`---` rules — renders as literal text. The user confirmed the full
mapping (links, headings, emphasis, callout markers, task checkboxes,
images, fence language tags + tilde fences) and chose **no escaping**
(`& < >` raw — the output targets the Slack composer, where HTML
entities would show literally).

## Goals / Non-Goals

**Goals:**
- `--format slack` on `ft notes export` with the agreed mapping table.
- Slack output renders correctly when pasted into the Slack composer:
  no literal `#`, `**`, `[x](y)`, `![…](…)`, or `- [ ]` residue.
- The `ExportTarget` seam survives with **stateless** targets; the only
  driver change is one additive `LineContext` field that `commonmark`
  ignores.
- `--format commonmark` output is byte-identical to today.

**Non-Goals:**
- **No escaping.** `&`, `<`, `>` pass through raw (composer-first
  contract). An escape option for API consumers can be added later.
- **No full CommonMark inline parser.** The emphasis pass is a
  delimiter scanner with CommonMark flanking rules for opener
  detection, not a spec-complete emphasis state machine. Nested
  emphasis inside headings and `***` runs are handled, but pathological
  nesting may degrade (Slack's own nested formatting is unreliable).
- **No tables or horizontal rules.** They stay literal (Slack can't
  render them in message text); documented.
- **No language highlighting / no Block Kit.** Output is plain mrkdwn
  text; code fences lose language tags (Slack has no highlighting).
- **No `plaintext` target** — still unimplemented, still rejected.

## Decisions

### D1. `LineContext.opened_fence` — the only driver change
Fence language-tag stripping must fire only on the line that *opens* a
fence. A line-local heuristic (` ```lang ` pattern) misfires on real
content lines that look like opening fences inside a fence (e.g. a
markdown doc whose code block contains ` ```rust ` as a literal).
`LineSkipState::classify` already tracks the open/close transition
internally, so the driver gains one accessor (`opened_fence`) surfaced
through `LineContext`; the Slack target stays stateless and
`&'static`. *Alternatives rejected:* interior-mutable target state
(`Cell`/`Mutex` on a `static`) — breaks the stateless-target pattern;
line-local regex — corrupts in-fence content lines.

### D2. Inline scanner first, structural rewrites second
Links, images, wikilinks, embeds, and emphasis all rewrite inline
content, and their rewrites must not re-trigger each other (a heading
converted to `*H*` must not be re-scanned as emphasis). The Slack
target therefore runs **one** left-to-right scanner per non-code line
(reusing the existing backtick-run machinery from the CommonMark
wikilink scanner): code spans copied verbatim, then each construct
rewritten once. Structural line rewrites (heading → `*H*` wrap,
blockquote `[!…]` marker strip, task `[ ]` drop) run **after** the
scanner, on the already-converted line, so the scanner only ever reads
source text — the heading wrapper is emitted directly into the output
and never re-scanned. *Alternatives rejected:* sequential regex passes
— `*H*` generated by the heading step would be re-read as emphasis;
structural-first ordering — a heading converted to `*H*` before the
scan would then be re-scanned as `_H_` (italic, losing the bold).

### D3. Emphasis delimiter rules
Delimiter runs (`***`, `**`, `*`, `~~`, `_`) use CommonMark flanking
for opener detection — a delimiter flanked by alphanumerics on the
inside (or followed by whitespace) is literal, which keeps `snake_case`
and `2 * 3` intact — with first-match closer pairing. Mapping:
`**x**` → `*x*`, `*x*` → `_x_`, `_x_` → `_x_` (already valid Slack),
`~~x~~` → `~x~`, `***x***` → `*_x_*`.

### D4. Links and images degrade gracefully
`[text](url)` with an `http(s)`/`mailto` URL → `<url|text>` (Slack's
syntax; markdown titles dropped). Non-URL targets (`[text](foo.md)`,
internal notes) → display text only — a relative path is not a link in
Slack. `![alt](src)` with an http(s) src → the **bare URL** (Slack
autolinks and unfurls a thumbnail); otherwise → alt text (or nothing
when absent). Embeds `![[img.png]]` → display text or target filename
— vault-local files are unreachable from Slack.

### D5. Structural rewrites
- Headings: `#{1,6} ` prefix → `*`, closing `*` appended — level lost.
- Callouts: after the blockquote `>` prefixes, a leading `[!word]`
  token is stripped (`> [!note] Title` → `> Title`); applies to any
  callout type incl. malformed `[!ft-source]` lines (canonical ones are
  dropped entirely before this).
- Task lines: `- ` / `* ` / `+ ` + `[ ]` / `[x]` → the bullet char
  alone; indent and emoji metadata kept; `[x]` state dropped.

### D6. Fence normalization
Opening fence with a language tag → bare ` ``` `; `~~~`-delimited
fences (open and close lines) → ` ``` `. Content inside fences is
verbatim. Fence-length edge cases (e.g. a 3-backtick content line
inside a 4-tilde fence) are accepted as rare limitations, documented
in tests.

### D7. No escaping (`& < >` raw)
The command's stated purpose is pasting into Slack; the composer does
not decode HTML entities, so `&amp;` would show literally. Raw `&`/`<`/`>`
render correctly in the composer. API consumers (chat.postMessage) are
a future concern; the API-docs escaping rules would then be an opt-in
flag, not the default.

## Risks / Trade-offs

- [Nested emphasis in headings (`# **foo**` → `***foo***` → `*_foo_*`)]
  → The `***` case is handled explicitly in the scanner; deeper nesting
  is accepted as a Slack-inherent limitation and covered by unit tests
  locking the common cases.
- [Raw `>` / `<` in prose could accidentally form `<url|text>`-looking
  strings in Slack] → Rare; Slack only misparses well-formed
  `<…|…>` patterns; documented in the guide as a consequence of the
  no-escaping decision.
- [Emphasis scanner false positives on pathological delimiter soup]
  → Flanking rules + first-match pairing + a locked unit-test table;
  worst case a stray `*` renders literally, never corrupts structure.
- [Fence-length edge: backtick content inside tilde fences] → Accepted
  and documented; tilde fences are rare in vault notes.
- [Slack may treat ` ```lang ` permissively (ignoring the tag)] →
  Stripping the tag is harmless in either case and is the safe
  cross-version behavior.

## Migration Plan

Additive CLI surface: `--format slack` is a new value; `--format
commonmark` and default behavior are unchanged, so no migration or
rollback concerns. Docs (guide + capability spec) updated in the same
change.

## Open Questions

None — the mapping and scope decisions were confirmed by the user.
